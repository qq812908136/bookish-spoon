# 督办系统（Task Supervision System）

面向小团队（5-20 人）的轻量级任务督办/跟踪系统。解决任务分散、进度失控、问题滞后、缺乏闭环四大痛点。

## 特性

- **统一任务池**：所有任务集中管理，支持筛选、搜索、排序、分页
- **5 态状态机**：待启动 → 进行中 → 已逾期 → 已闭环 / 已撤销，含自动逾期触发
- **三层预警**：即将到期预警、已逾期预警、长期待激活预警，自动生成站内消息
- **站内消息**：任务指派、状态变更、预警通知，导航栏红点轮询（每 30 秒）
- **侧滑面板**：任务详情从右侧滑出，不跳转页面，支持内联编辑
- **权限控制**：管理员（admin）/ 负责人（owner）两种角色，数据级权限过滤
- **零配置启动**：SQLite 单文件存储，双击 start.bat 即可运行

## 快速开始

### 环境要求

- Python 3.10+
- Windows 操作系统

### 启动方式

1. 解压项目文件夹
2. 双击 `start.bat`
3. 首次启动会弹出初始化向导，创建管理员账号
4. 浏览器自动打开 `http://127.0.0.1:5000`

> 如果浏览器没有自动打开，手动访问 `http://127.0.0.1:5000`

### 让同事也能访问（局域网模式）

默认只监听 `127.0.0.1`，**只有这台电脑能打开**。需要小团队共用时分两步：

1. 右键 `开启局域网访问.bat` → **以管理员身份运行**（放行防火墙，每台电脑只需一次）
2. 之后改用 `局域网启动.bat` 启动（不要再用 `start.bat`）

> 只跑 `开启局域网访问.bat` 是不够的 —— 它只管防火墙，服务本身仍只监听本机，
> 端口开得再大也没人连得进来。两个脚本必须配合。

> 生产环境的完整部署（WSGI 服务器、HTTPS、备份）见 `docs/生产部署指南.md`

### 命令行启动

```bash
pip install -r requirements.txt
python src/app.py
```

> 运行测试：`python -m unittest tests.test_suite`（161 项，约 7 分钟）
> 生成测试报告：`python tests/generate_test_report.py`（默认输出到 `docs/测试报告/`）

### 可选配置（.env）

所有配置项**都可以不配**，不配则沿用默认值。需要调整时：

1. 复制 `.env.example` 为 `.env`（放在项目根目录，或打包后放在 exe 同级目录）
2. 按需修改，重启生效

优先级：**系统环境变量 > `.env` 文件 > 代码默认值**

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `SECRET_KEY` | **自动生成**（见下） | 会话签名密钥。通常无需配置 |
| `HOST` | `127.0.0.1` | 仅本机访问。需局域网共享请改用 `局域网启动.bat`，不建议直接改这里 |
| `PORT` | `5000` | 端口被占用时可改成 5001、8080 |
| `DEBUG` | `false` | 开启后异常会显示堆栈，**发布时必须为 false** |
| `SERVER` | `flask` | 生产部署可设 `waitress`（需先 `pip install waitress`） |
| `LOG_LEVEL` | `INFO` | 排查问题时可临时改 `DEBUG` |
| `LOGIN_MAX_ATTEMPTS` | `5` | 连续失败几次后锁定账号 |
| `LOGIN_LOCKOUT_MINUTES` | `15` | 锁定持续时长（分钟），到期自动解锁 |
| `PASSWORD_MIN_LENGTH` | `8` | 密码最小长度（不追溯已有账号） |
| `PASSWORD_REQUIRE_STRENGTH` | `true` | 是否拦截弱口令（纯数字/纯字母/常见口令/同用户名） |
| `CSRF_ENABLED` | `true` | 是否校验写请求的 CSRF 令牌，**生产务必保持开启** |
| `CSRF_TOKEN_MAX_AGE` | `86400` | CSRF 令牌有效期（秒），页面停留超时后提交需刷新 |

### 会话签名密钥

**首次启动自动生成**随机密钥，写入 `data/secret.key` 并长期复用，**每个部署实例的密钥都不相同**，源码与打包物中不含任何可用密钥。因此通常不需要任何配置。

仅在以下情况需用 `SECRET_KEY` 显式指定：

- 多台机器部署且希望共享会话（负载均衡后不频繁掉线）
- 部署目录只读，无法写入 `data/secret.key`
- 需要轮换密钥（改配置并重启，所有用户会被强制重新登录）

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

> `data/secret.key` 已加入 `.gitignore` 与交付包排除名单，**切勿手动提交或随包分发** —— 一旦共用，密钥防护就失效了。

### 日志

运行日志写在 `logs/supervision.log`（打包后落在 exe 同级目录），按大小自动轮转：单文件 2 MB、保留 5 份。
日志目录不可写时会**自动降级为仅控制台输出**，不会导致启动失败。

## 使用指南

### 首次使用

1. 双击 `start.bat` 启动系统
2. 在初始化向导中创建管理员账号（用户名、显示名、密码）
   - 密码至少 **8 位**，不能全是数字或全是字母，也不能是 `123456`、`password` 这类常见口令
3. 用管理员账号登录
4. 在「用户管理」中新增团队成员账号
5. 在「任务列表」中创建并指派任务

### 角色 说明

| 角色 | 能力 |
|------|------|
| 管理员 (admin) | 创建/编辑/删除所有任务、用户管理、系统设置、重新打开闭环任务 |
| 负责人 (owner) | 创建个人任务、编辑自己的任务、查看全部任务（只读他人）、更新进度 |

### 任务状态流转

```
待启动 → 进行中 → 已闭环
  ↓         ↓        ↑(管理员重开)
已逾期 → 进行中
  ↓
已闭环 / 已撤销 ←(管理员重新激活)→ 待启动
```

- **已逾期**由系统自动触发（每 5 分钟扫描超期任务）
- **已闭环**和**已撤销**为终态，仅管理员可重新打开

### 预警机制

| 层级 | 触发条件 | 通知对象 |
|------|----------|----------|
| 即将到期 | 截止日期前 N 天（默认 3 天） | 负责人 |
| 已逾期 | 超过截止日期未闭环 | 负责人 + 管理员 |
| 长期待激活 | 创建后 N 天未启动（默认 7 天） | 负责人 + 管理员 |

预警天数可在「系统设置」中调整。

## 常见问题

**Q: 关闭命令行窗口后系统停止了？**
A: 是的，关闭 start.bat 的命令行窗口即停止服务。需要保持窗口打开。

**Q: 数据保存在哪里？**
A: 所有数据保存在 `data/supervision.db` 文件中（SQLite）。备份此文件即可备份所有数据。

**Q: 登录时提示「失败次数过多，账号已临时锁定」？**
A: 这是 V4 新增的防爆破保护：同一台电脑对同一个账号连续输错 5 次，会锁定 15 分钟，
**期间即使输对密码也会被拒绝**。等 15 分钟会自动解锁，不用做任何操作。

如果急着用，有两个办法：
1. 换一台电脑登录（锁定按「电脑 IP + 用户名」分别计算，不会牵连其他电脑）；
2. 重启程序会清空计数（限流状态只存在内存里，不落盘）。

想放宽限制可在 `.env` 里调：`LOGIN_MAX_ATTEMPTS=10`、`LOGIN_LOCKOUT_MINUTES=5`。

**Q: 为什么现在改密码要求 8 位了，还不能用纯数字？**
A: V4 新增了密码强度校验，规则是：至少 8 位、不能全是数字或全是字母、不能是
`123456`/`password` 这类常见口令、不能和用户名相同。

注意这是**不追溯**的：早期创建的 6 位密码账号**仍然可以正常登录**，
只是下次改密码时才需要符合新规则。

**Q: 提交表单时提示「请求未通过安全校验」？**
A: 这是 V4 新增的 CSRF 防护。系统会给每个页面签一个加密令牌，提交时校验，
用来防止恶意网站借你的登录身份偷偷发起操作。

看到这个提示通常有两个原因：
1. **页面开太久了**（超过 24 小时没动），令牌过期了 —— 刷新页面重新操作即可；
2. **在另一个标签页重新登录过** —— 登录会轮换令牌，把旧标签页刷新一下。

如果是自己开发的页面出现这个提示，检查表单里有没有带上
`<input type="hidden" name="csrf_token" value="{{ csrf_token }}">`。

**Q: 忘记管理员密码怎么办？**
A: 删除 `data/supervision.db` 文件后重启系统，会重新进入初始化向导（注意：会丢失所有数据）。

**Q: 如何修改端口？**
A: 在 `.env` 里写 `PORT=8080` 然后重启即可（无需改代码）。改完后防火墙放行规则也要跟着换端口。

**Q: 升级后同事访问不了了？**
A: 这是 V4 的刻意调整。以前默认对整个局域网开放，很多人并不知情；现在默认只监听 `127.0.0.1`。
需要局域网访问时，先用管理员身份跑一次 `开启局域网访问.bat`，之后改用 `局域网启动.bat` 启动。

**Q: 为什么改了仓库里的 bat，离线程序里没变化？**
A: 这个问题已修复。以前每次构建都会从 v3 基线重新复制离线目录，把你的改动冲掉。
现在仓库根的 bat 是唯一真相源，构建时会自动同步进离线程序目录。
这些脚本是自适应的（有 exe 跑 exe，没有就用 Python 跑源码），所以一份文件两处通用。
