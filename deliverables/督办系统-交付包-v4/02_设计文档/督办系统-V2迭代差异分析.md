## 1. 模板分析（基准画像）

### 1.1 设计语言

| 维度 | 模板取值 |
|------|---------|
| 技术栈 | Tailwind CSS（原子类）+ Lucide SVG 图标 + Inter / Noto Sans SC 字体 |
| 主色 | 品牌蓝 `#2563eb`（brand-600），辅色板 `#3b82f6 / #1d4ed8` |
| 状态色 | 待启动灰 `#6b7280` · 进行中琥珀 `#f59e0b` · 已逾期红 `#ef4444` · 已闭环绿 `#10b981` · 已撤销浅灰 |
| 页面底色 | `#f5f5f7` 浅灰，卡片纯白 |
| 卡片风格 | `rounded-xl`（12px 圆角）+ 轻阴影 `shadow-card`，hover 上浮 1px |
| 状态标签 | 药丸形（圆角 9999px）浅底深字，带色点 |
| 导航布局 | **顶部固定导航栏**（sticky），非左侧边栏 |
| 交互动效 | 右侧滑入抽屉（0.3s 缓动）、Toast 通知、卡片 hover 微动效 |
| 深色模式 | 支持（顶栏一键切换，含全套暗色样式） |
| 响应式 | 统计卡 2→3→6 列自适应；主区 1→12 栅格两栏；抽屉全屏→560px |

### 1.2 页面结构（单页应用）

```
顶栏：Logo | 标题+日期副标题 …… 时间范围下拉 | 用户pill | 退出 | 消息铃铛(红点) | 深色切换
主区：
  ├─ 6 个统计卡（任务总数/待启动/进行中/已逾期/已闭环/闭环率）→ 点击即筛选
  ├─ 左栏：今日督办焦点（逾期优先排序的滚动列表，点击开详情抽屉）
  └─ 右栏：任务闭环矩阵（按 Owner 汇总：任务数/待启动/进行中/已逾期/已闭环/闭环率，
           分页，点数字按 Owner+状态筛选，点名字开 Owner 抽屉）
抽屉层：
  ├─ Owner 抽屉：该负责人任务列表 + 「推送提醒」按钮
  ├─ 任务详情抽屉：3 个页签（详情 / 过程证据 / 阻塞记录）
  │    ├─ 详情：全部字段行内可编辑（contenteditable / 下拉 / 日期），进度%+进度条
  │    ├─ 过程证据：text/link/file 三类证据条目 + 添加表单
  │    └─ 阻塞记录：open/resolved 两态条目 + 添加表单
  └─ 消息抽屉：消息列表 + 全部已读
弹窗层：进度情况弹窗（进度条 + 时间线）
其他：登录页（左品牌介绍右登录卡、字段级错误、记住我、密码可见切换、演示账号提示）
```

### 1.3 模板的状态机与角色

- **5 态状态机**：待启动 / 进行中 / 已逾期 / 已闭环 / 已撤销 —— 与现有系统**完全一致**
- **角色**：管理员 / 负责人 —— 与现有系统一致（模板登录演示了两种角色）

## 6. 待确认问题（苏格拉底式，逐条作答）

**Q1 · 任务字段扩展**：模板行动比现有任务多出「部门、协同方、来源会议、会议日期、行动资产ID、风险点、引用原话」7 个字段。全部照搬会让新建表单变长，且部分字段（来源会议）是模板特有的会议蒸馏场景。
- A. 全部新增，表单中均可选填（完全对齐模板）
- B. 精简新增：进度% + 风险点 + 协同方（其余不建字段）✅ 建议
- C. 只新增进度%（最保守）

**Q2 · 证据与阻塞记录**：模板的「过程证据 / 阻塞记录」两个页签需要新建两张数据表和相应路由。
- A. 完整实现（证据三类型 + 阻塞两态 + 添加表单，owner 可为自己的任务添加，admin 全部可操作）✅ 建议
- B. 简化为一种「过程备注」记录，不分类
- C. 本次不做，仅保留页签占位

**Q3 · 任务详情交互**：模板用右侧抽屉 + 行内编辑；现有是独立详情页。
- A. 完全对齐模板：列表点行开抽屉，抽屉内行内编辑（保留原详情路由供消息跳转/降级）✅ 建议
- B. 抽屉仅作展示，编辑仍跳独立表单页

**Q4 · 导航信息架构**：现有侧边栏有 7 个入口（概览/任务/通知/设置/用户管理/系统设置 + 退出），模板顶栏没有传统菜单。
- A. 顶栏放主导航（概览/任务/设置/用户管理/系统设置），通知改为铃铛图标 + 消息抽屉（不再保留独立消息页）✅ 建议
- B. 同上，但额外保留独立消息中心页
- C. 保留左侧边栏布局，仅替换视觉皮肤

**Q5 · 深色模式**：模板支持一键切换。
- A. 实现（手动切换 + 记忆偏好，默认浅色）✅ 建议
- B. 本次不做

**Q6 · 时间范围筛选作用域**：模板的「全部/本年/本季/本月/本周」下拉。
- A. 仅作用于仪表盘（统计卡 + 焦点列表 + 闭环矩阵），任务列表保持现有筛选 ✅ 建议
- B. 全局生效（含任务列表）

**Q7 · 优先级体系**：现有 urgent/high/medium/low 四级，模板是「P0 高 / P1 中 / P2 低」三级。
- A. 保留现有四级，仅显示样式对齐模板（无数据迁移风险）✅ 建议
- B. 切换为 P0/P1/P2 三级（需要写数据迁移脚本）

**Q8 · 「推送提醒」的实现**：模板抽屉里的推送提醒按钮。
- A. 即给该任务 Owner 发一条站内提醒消息（复用现有消息系统，admin 可用）✅ 建议
- B. 站内信 + 邮件同时发（邮件通道 V1 未实现，需额外开发）

**Q9 · 闭环率口径**：模板为「已闭环 ÷ 任务总数」。
- A. closed ÷ (总数 − 已撤销)，排除已撤销更符合督办语义 ✅ 建议
- B. 完全照搬模板 closed ÷ 总数

## 8. 风险与说明

1. **字体与图标离线化**：模板用 CDN 字体（base64 内嵌 Inter）。打包为离线 exe 时需下载 Lucide 图标库与 Noto Sans SC 字体到 `static/`，否则内网无法加载 —— 将在批次一处理。
2. **单页 vs 多页**：模板是纯前端单页应用；现有系统是 Flask 多页应用。方案是**保留 Flask 多页架构**，用模板的视觉语言重构每个页面 + 抽屉用局部加载，不做大规模前后端分离改造（保护全部现有功能与测试资产）。
3. **数据兼容**：所有表结构变更采用 `ALTER TABLE ... ADD COLUMN` + 建表 IF NOT EXISTS，老数据库启动自动升级，数据不丢失。
4. **行内编辑与权限**：抽屉内编辑严格复用现有 `can_edit_task` 权限判断，owner 只能改自己的任务，防止权限退化。
