# 督办系统 — 生产部署指南

> 适用版本：V4（DEF-004 整改后）
> 最后更新：2026-08-31

---

## 一、先想清楚：你要哪种部署形态

系统的**网络暴露范围**由 `HOST` 这一个配置决定，三种形态对应三种取值：

| 形态 | HOST | 谁能访问 | 怎么启动 | 适合场景 |
|---|---|---|---|---|
| **本机** | `127.0.0.1`（默认） | 只有这台电脑 | 双击 `start.bat` | 自己一个人用；**默认就是这个** |
| **局域网** | `0.0.0.0` | 同一网络内所有设备 | 先跑一次 `开启局域网访问.bat`，之后用 `局域网启动.bat` | 小团队内网共用 |
| **生产** | `0.0.0.0` + WSGI + HTTPS | 按你的网络规划 | 见本文第四节 | 正式投入使用 |

**V4 起默认值是 `127.0.0.1`。** 这是一次安全收紧：以前默认 `0.0.0.0`，任何一台部署机器都会默认对整个局域网开放，很多人并不知道自己开了这个口子。现在局域网开放是一个**需要主动选择**的动作。

---

## 二、本机模式（默认，什么都不用配）

双击 `start.bat`，浏览器打开 <http://127.0.0.1:5000>。

就这一步。不需要改任何配置。

---

## 三、局域网模式（让同事也能访问）

两步，缺一不可：

**第 1 步：放行防火墙（每台电脑只需做一次，需要管理员权限）**

右键 `开启局域网访问.bat` → **以管理员身份运行**。它会在 Windows 防火墙上放行 5000 端口。

**第 2 步：用局域网模式启动**

双击 `局域网启动.bat`。它做的事情只有一件——启动时带上 `HOST=0.0.0.0`：

```bat
set HOST=0.0.0.0
```

启动后会打印出局域网地址（形如 `http://192.168.31.199:5000`），把这个地址发给同事即可。

> **为什么不能只跑 `开启局域网访问.bat`？**
> 那个脚本只管防火墙。如果服务本身仍只监听 `127.0.0.1`，端口开得再大也没人连得进来。两个脚本必须配合。

> **安全提醒**：局域网模式下，同一网段内**任何设备**都能打开本系统。请确认网络可信，不要在公共 WiFi 下使用。

## 四、生产部署（正式投入使用）

内网小规模使用，跑 Flask 自带的开发服务器一般也够用。但它不是为生产设计的（无并发调优、无超时保护、Werkzeug 官方明确不建议用于生产）。正式上线建议按下文加固。

### 4.1 换用 WSGI 服务器（Waitress）

Waitress 是纯 Python 的 WSGI 服务器，Windows 上开箱即用，不需要编译。

```bash
pip install waitress
```

然后设置环境变量（或写进 `.env`）：

```ini
SERVER=waitress
HOST=0.0.0.0
PORT=5000
```

启动方式不变。看到日志里出现 `WSGI 服务器: waitress` 即表示生效。

> Waitress 是**可选**依赖。如果设了 `SERVER=waitress` 但没装，系统会在日志里报错并**自动回退**到 Flask 开发服务器 —— 不会因为缺一个可选包就起不来。
>
> **离线程序（`.exe`）已内置 Waitress**：V4 起的离线包已将 `waitress` 一并打包进 `_internal/`，直接用 `生产启动.bat` 即以 Waitress 运行，无需额外安装。源码部署仍需先 `pip install waitress`（已写入 `requirements.txt`）。

仓库根已提供 `Caddyfile.example` 样例，可直接复制使用（见上方示例）。

### 4.2 启用 HTTPS

HTTP 是明文传输，登录密码和会话 Cookie 在网络上裸奔。只要数据有一定敏感性，就应该上 HTTPS。

**推荐方案：用 Caddy 做反向代理（最省事）**

Caddy 能自动申请和续签证书，配置只有几行：

```Caddyfile
supervision.your-company.com {
    reverse_proxy 127.0.0.1:5000
}
```

然后让系统只监听本机（更安全）：

```ini
HOST=127.0.0.1
SERVER=waitress
```

外网流量经 Caddy（443）转发到本机的 5000 端口，系统本身不直接暴露。

**内网无域名时**：可以用自签名证书，但浏览器会告警异，需要每个人手动信任一次。内网可信环境下，也可以选择暂不启用 HTTPS，但要知道密码是明文传输的。

### 4.3 开启会话 Cookie 的 Secure 标记

启用 HTTPS 后，**必须**加这一条：

```ini
SESSION_COOKIE_SECURE=True
```

它会让浏览器只在 HTTPS 连接下才发送会话 Cookie。

> ⚠️ **在纯 HTTP 环境下不要设成 True**，否则浏览器根本不会回传 Cookie，表现为「登录后立刻又跳回登录页」。

### 4.4 反向代理下务必透传客户端 IP

登录限流是按**客户端 IP + 用户名**计数的（DEF-005）。如果系统跑在 Nginx / Caddy 后面，
而代理没有把真实客户端 IP 传进来，那么所有请求在应用看来都来自同一个地址——
结果就是**一个人被锁，全公司陪绑**，审计日志里的 IP 也全是错的。

**第一步：代理层传 IP**

Caddy 默认就会加 `X-Forwarded-*`，无需额外配置：

```caddyfile
reverse_proxy localhost:5000
```

Nginx 需要显式设置：

```nginx
location / {
    proxy_pass       http://127.0.0.1:5000;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Host              $host;
}
```

**第二步：让应用信任代理头**

光有代理转发还不够——Werkzeug 默认忽略 `X-Forwarded-*`，`request.remote_addr`
取到的仍是代理 IP。需要在 `.env` 里开启：

```ini
BEHIND_PROXY=True
BEHIND_PROXY_TRUSTED_HOPS=1
```

> `TRUSTED_HOPS` 必须**等于**你实际的代理层数（1 层 = 只有 Nginx/Caddy，最常见；
> 2 层 = CDN + Nginx）。**写大了会有安全问题**：应用会信任请求里更靠前的那一段
> `X-Forwarded-For`，攻击者可以自己伪造它来绕过登录限流。
>
> 另外，这个开关在**没有**反向代理时务必保持 False（默认值）——
> 否则任何人都能伪造 `X-Forwarded-For` 让限流失效。

### 4.5 让服务开机自启 / 崩溃自拉起

Windows 上推荐用 [NSSM](https://nssm.cc/) 把启动命令包装成系统服务：

```
服务路径：C:\督办系统\督办系统.exe
启动目录：C:\督办系统
环境变量：HOST=0.0.0.0  SERVER=waitress
```

这样机器重启后自动恢复，进程挂了也能自动拉起。

---

### 4.6 一键生产启动（生产启动.bat）

仓库随附的 `生产启动.bat` 把上面几步串成一个动作，是生产环境的推荐入口：

1. 启动前**先调用 `备份数据.bat` 备份一次 `data/`**，防止升级或异常损坏；
2. 设置 `SERVER=waitress`（离线程序已内置 Waitress，直接生效）；
3. 监听 `127.0.0.1`，配合下面的反向代理对外暴露；
4. 自动判断运行方式：有 `督办系统.exe` 跑离线程序，否则用 Python 跑源码。

脚本里还留了 `SESSION_COOKIE_SECURE`、`BEHIND_PROXY`、`BEHIND_PROXY_TRUSTED_HOPS`
的**注释占位**，按 §4.3 / §4.4 的实际需要取消注释即可，无需改别处。

> 直接用 `生产启动.bat` 替代双击 `start.bat`，生产部署就一致且不易漏配置。

## 五、配置项速查

全部配置都支持三种方式，优先级从高到低：**系统环境变量 > `.env` 文件 > 代码默认值**。

| 配置 | 默认值 | 说明 |
|---|---|---|
| `HOST` | `127.0.0.1` | 监听地址。`0.0.0.0` 开放局域网 |
| `PORT` | `5000` | 监听端口 |
| `DEBUG` | `False` | **生产必须为 False** |
| `SERVER` | `flask` | `waitress` 走 WSGI 服务器 |
| `SECRET_KEY` | 自动生成 | 会话签名密钥，一般不用管 |
| `SESSION_COOKIE_HTTPONLY` | `True` | 禁止 JS 读取会话 Cookie |
| `SESSION_COOKIE_SAMESITE` | `Lax` | 跨站 POST 不带 Cookie（CSRF 防线之一，另见 `CSRF_ENABLED`） |
| `SESSION_COOKIE_SECURE` | `False` | 仅 HTTPS 传输；**启用 HTTPS 后设 True** |
| `CSRF_ENABLED` | `True` | 写请求 CSRF 令牌校验，**生产务必保持开启** |
| `CSRF_TOKEN_MAX_AGE` | `86400` | CSRF 令牌有效期（秒），页面停留超时后提交需刷新 |
| `BEHIND_PROXY` | `False` | 反向代理后设 True，否则限流会把所有人记成同一 IP |
| `BEHIND_PROXY_TRUSTED_HOPS` | `1` | 信任的代理层数，**必须等于实际层数** |
| `LOGIN_MAX_ATTEMPTS` | `5` | 连续失败几次后锁定「IP + 用户名」 |
| `LOGIN_LOCKOUT_MINUTES` | `15` | 锁定持续时长（分钟），到期自动解锁 |
| `PASSWORD_MIN_LENGTH` | `8` | 密码最小长度（不追溯已有账号） |
| `PASSWORD_REQUIRE_STRENGTH` | `True` | 拦截纯数字/纯字母/常见口令/与用户名相同 |
| `LOG_LEVEL` | `INFO` | 日志级别 |
| `LOG_MAX_BYTES` | `2097152` | 单日志文件上限（2MB），超出自动轮转 |
| `LOG_BACKUP_COUNT` | `5` | 保留的历史日志个数 |

完整模板见仓库根的 `.env.example`。

## 六、运维要点

### 备份什么

真正的业务数据只有两个文件，**定期备份这两个就够了**：

| 文件 | 作用 | 丢了会怎样 |
|---|---|---|
| `data/supervision.db` | 全部用户、任务、消息 | 数据全没了 |
| `data/secret.key` | 会话签名密钥 | 所有人被强制重新登录（**不会**丢数据） |

`secret.key` 是首次启动时自动生成的，**每台机器都不一样**。它不在交付包里，也不会进 git —— 这是刻意的，否则所有部署实例会共用同一把密钥。

> 备份 `secret.key` 不是必须的，但备份了可以保证恢复后用户不用重新登录。

### 如何备份（数据备份工具）

仓库随附 `备份数据.bat`，一键把上面两个文件复制到带时间戳的 `backups/YYYYMMDD_HHMMSS/` 目录：

```bat
备份数据.bat              :: 手动备份一次（双击即可）
备份数据.bat nopause      :: 同一份，但不停留等待（供计划任务/脚本调用）
```

恢复时把备份里的 `supervision.db`（和 `secret.key`）覆盖回 `data/` 即可。

> **配置定期备份**：用 Windows「任务计划程序」新建一个每天凌晨运行的任务，
> 操作为 `备份数据.bat nopause`（起始于督办系统目录）。这样无需人工干预即实现定期备份。
> 注意 `backups/` 会持续增长，请另外设置保留策略（如只保留最近 30 天）。

### 日志在哪

`logs/supervision.log`，超过 2MB 自动轮转，保留 5 个历史文件。排查问题时先看这里。

### 端口被占用

改 `PORT` 即可，例如 `.env` 里写 `PORT=8080`。
