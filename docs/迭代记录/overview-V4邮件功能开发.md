## 二、关键设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 发送方式 | **落库队列 + 复用现有 5 分钟扫描** | 零新增线程；天然支持重试、限频、可重发 |
| 并发量 | 按人**合并** + 管理员只收日报 + 每轮限量 20 封 | 500 封/天 → 约 30 封/天，规避个人邮箱风控 |
| 认证失败 | **立即熔断，必须人工恢复** | 用错误密码重试一天能试出几千次失败登录，多数邮箱商会直接封号 |
| 其他失败 | 连续 10 封后暂停 60 分钟，自动试探恢复 | 网络抖动这类可自愈，不该每次都要人介入 |
| 默认状态 | **`MAIL_ENABLED=False`** | 铁律「不配置 = 行为不变」，保护已发行的离线 exe |
| 加密 | `hashlib` 自建 XOR 流密码 | 引入 `cryptography` 要重打包 exe，成本过高；等保场景再换 |
| 去重键 | 邮件**独立**于站内信 | 共用会被「未配邮件的沉默期」吃掉去重名额 |
| 配置优先级 | env > `.env` > 数据库 > 默认值，被 env 锁定的项在页面标注 | 避免「保存了没变化」的假故障 |

## 三、本轮修掉的三个真实 bug

1. **SMTP 授权码存不进去**——`save_config` 组装表单字典时漏了 `smtp_password` 键。表面「保存成功」，实际每次重填都丢，且因为没配过邮件，现象上完全看不出来。
2. **整页提交返回一屏 JSON**——`/tasks/<id>/send-mail` 原本只返回 JSON，从详情页整页提交时会看到满屏裸 JSON。加 `_mail_result()` 按 `X-Requested-With` 自适应。
3. **抽屉每次打开打 14 条 SQL**——`get_mail_config()` 循环内逐键查库。改为一次 `get_all_config()` 后内存比对。
4. **登录页与初始化向导页加载旧样式**（打包后冒烟才暴露）：静态资源缓存串 `main.css?v=20260830af` 写死在每个模板里，改 CSS 时只升了 `base.html`，而 `login.html` / `setup.html` **不继承 `base.html`**，版本号没跟上 → 浏览器继续用缓存里的旧文件。已改为集中一处（`config.STATIC_VERSION` → 上下文注入 → 模板写 `v=static_version`），并加 2 项测试守住。

前两个是端到端冒烟脚本跑出来的，单看代码都不容易发现；第 4 个是打包成 exe 后实跑才发现的，开发模式下因为浏览器强刷过而一直没暴露。

## 四、测试写法上踩的三个坑（已沉淀进记忆）

- **模拟复选框未勾选要「删键」而不是「传空串」**：服务端判断 `'key' in form`，空串的键依然存在，测不出取消勾选的效果。
- **模板 `if/elif` 会让断言落到错误的分支**：熔断横幅在未配置时被「功能未启用」顶掉，必须先造好前置状态。
- **`assertNotIn` 会被页面其他区块污染**：失败邮件无论怎么筛选都会显示在独立的「失败清单」卡里，判断筛选是否生效要改用「共 N 条」计数。

## 六、两处 SPEC 口径（✅ 用户已确认，2026-09-03）

SPEC 内部有张力的两处，开发时先按拟定口径实现，2026-09-03 提交复核后
**用户确认均维持现状**。已回写 `docs/督办系统-V4邮件功能需求清单.md` 第 9 章，
含代码依据与未采用的备选方案。

1. **R-1 与 R-2 的张力** → 确认「照发」

   - R-1：预警邮件收件人 = **负责人 + 所有在职管理员**
   - R-2：管理员**只收每日汇总日报**，不收单任务零散邮件

   确认口径：**管理员不会收到他人任务的零散邮件**（全组织逾期情况合并进 09:00 日报）；
   但若管理员本人就是某项任务的负责人，那封按人合并的提醒**照发**——他是以负责人身份
   收到，不是以管理员身份被抄送。

   代码依据：`enqueue_overdue_warnings()` 按 `get_overdue_tasks_by_assignee()` 遍历
   （纯负责人维度）；只有 `enqueue_daily_reports()` 用 `role_filter='admin'` 按角色群发。

2. **保存配置不自动解除熔断** → 确认「不自动」

   因认证失败熔断后，即使改好 SMTP 配置并保存，仍需再点一次「修正后恢复发送」。
   刻意如此：熔断时页面上显示的大概率就是那个错误密码，自动恢复会让
   「改了但好像没生效」的排查变得更难——分不清是没生效还是又失败了。

   代码依据：`save_config()` 只调 `reset_fail_streak()`，**不碰** `set_circuit_state()`。
