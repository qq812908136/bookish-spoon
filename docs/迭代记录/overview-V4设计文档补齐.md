## 六、过程中的两个环境坑

1. **本机代理只放行 `api.github.com`，不放行 `github.com`** —— `git push` 握手失败，`curl https://github.com/` 报 CONNECT 502，直连 21 秒超时；但 `api.github.com` 返回 200。最终用 Git Data API 推送（blobs → trees → commits → PATCH ref），凭据从 `git credential-manager get` 取。
2. **API 建的 commit 与本地 commit 是兄弟提交**（内容相同、sha 不同）—— 不对齐的话下次 `git push` 会非快进失败。解决办法是用远端 commit 的元数据在本地重建出 sha 完全相同的对象再 `update-ref`。其中两个细节：提交信息必须按**字节**传子进程（否则 Windows 把 `\n` 转成 `\r\n`）；API 返回的时间是 UTC 但对象里存的是账号时区 `+0800`，靠遍历候选偏移反推。

两项已沉淀为技能 `github-api-push-when-blocked`（用户级），下次直接调用。
