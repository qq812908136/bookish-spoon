### 3.3 构建脚本补两处能力（`scripts/build_delivery_package.py`）

**① `RENAME_MAP` + `apply_renames()`** —— 复制后自动去掉易腐的「-最新」后缀。只作用于新生成版本，v3 基线不在写入路径上。

**② `sync_offline_exe()`** —— 修掉一个真实流程缺口：

```
此前：全量重跑脚本 → 05_离线程序 纯从 v3 复制 → exe 退回 v3 旧版，需手工补
现在：脚本自动用 dist/督办系统 的最新产物覆盖 exe 与 _internal/
      保留 data/（内置演示库）与 4 个离线 bat
      dist 缺失时打印警告，而非静默沿用旧 exe
```

**为什么必须补**：v3 与 v4 的 exe 哈希不同（`b6c39aa6` vs `bfe36347`，6206633 vs 6206682 字节），分别基于平铺结构与 src 分层结构打包。静默退回会让交付包与源码失去同源性。

## 四、本轮新踩的三个坑

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | 重建 v4 会永久丢失 src 分层 exe | `dist/` 在档位3重构时已归档到 `_archive/dist/` 并清空 | 先从 `_archive/dist/督办系统` 用 `cp -a` 拷回 `dist/督办系统`，再重建 |
| 2 | 冒烟请求返回 502 / WinError 10054 | 环境存在 HTTP 代理，拦截了 `127.0.0.1:5000` | `urllib.request.ProxyHandler({})` 禁用代理 |
| 3 | 请求报 WinError 10061 ConnectionRefused | exe 用 `cmd &` 启动会随该次 Bash 调用结束被回收 | 改用 `run_in_background: true` 启动 |

另外更正一处记忆偏差：导出路由是 **`/tasks/export`（xlsx）**，不是 `/export/tasks?format=csv`。
