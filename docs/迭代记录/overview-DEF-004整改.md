# 执行概览：DEF-004 代码侧整改（监听地址默认收回 127.0.0.1）

> 完成时间：2026-09-01 00:10
> 严重程度：**P1（一般）** —— 上线前安全整改清单的第二项

---

## 一、问题是什么

改之前，`src/config.py` 里是：

```python
HOST = _env_str('HOST', '0.0.0.0')
```

`0.0.0.0` 表示监听所有网卡。也就是说**每一台部署机器默认对整个局域网开放**，而使用者往往并不知道这件事 —— 启动脚本甚至会主动把局域网地址打印出来，让人以为这是推荐用法。

叠加另外两个因素，风险被放大：

- DEF-001（密钥硬编码）：任何拿到程序的人都能伪造管理员会话 —— **已修复**
- DEF-002（无 CSRF）：已登录用户可被诱导发起伪造请求 —— **部分缓解**

内网里只要有人能访问到这台机器的 5000 端口，就能打开登录页。

---

## 二、修复方案

### 核心改动一：默认只监听本机

| 项 | 改动前 | 改动后 |
|---|---|---|
| 默认监听 | `0.0.0.0` | **`127.0.0.1`** |
| 局域网开放 | 默认就是开的 | **显式动作**：必须双击 `局域网启动.bat` |
| 运行载体 | 只有 Werkzeug 开发服务器 | 支持 `SERVER=waitress` |
| 会话 Cookie | 无 SameSite | `HttpOnly` + `SameSite=Lax`，`Secure` 可配置 |

`局域网启动.bat` 做的事只有一件 —— 启动时设 `HOST=0.0.0.0`：

```bat
set HOST=0.0.0.0
```

### 核心改动二：三个启动脚本的职责理顺

| 脚本 | 职责 | 说明 |
|---|---|---|
| `start.bat` | 本机模式（默认） | 只监听 `127.0.0.1`，并提示需要局域网时该用什么 |
| `局域网启动.bat` | 局域网模式（新增） | 设 `HOST=0.0.0.0` 后启动，打印局域网地址 |
| `开启局域网访问.bat` | 只管防火墙 | 明确写出「本脚本只做一件事」，并提示要配合 `局域网启动.bat` |

> 之前很多人会以为只跑 `开启局域网访问.bat` 就够了。其实它只放通了防火墙端口，**服务本身仍只监听本机**，端口开得再大也没人连得进来。现在三个脚本的提示互相指向，不会再混淆。

### 核心改动三：5 个 bat 改为「运行方式自适应」

```bat
if exist "%~dp0督办系统.exe" goto :use_exe
REM 源码模式：用 Python 跑 src\app.py
...
:use_exe
set "RUN_BIN=%~dp0督办系统.exe"
```

目录里有 exe 就跑 exe，没有就用 Python 跑源码。**仓库根与离线程序从此共用同一份脚本**，不必再维护两套。

> 用 `goto` 而非括号块，是为了避开 cmd 的 delayed expansion 陷阱 —— 在 `(...)` 里 `set` 完立刻 `%VAR%` 取值会拿到旧值。

### 顺带修掉两个隐患

这两个都不是本次的主要目标，但如果不修，前面的改动会打折：

**1. 离线 bat 永远改不动**

每次构建都会从 v3 基线重新复制 `05_离线程序/`，把仓库根 bat 的改动全部冲掉。结果就是「改了启动脚本，离线程序里毫无变化」。

现在构建脚本新增 `sync_offline_bats()`，把仓库根 bat 同步进离线目录。已验证两者**字节完全一致**。

**2. 交付包里的缺陷清单永远是 v3 旧版**

`04_测试/` 只同步 `docs/测试报告/`，缺陷清单一直沿用基线版本 —— 于是交付包里写着「DEF-001 未修复」，而代码早就修好了。

现在额外同步 `缺陷清单-2026-08-31.md` 与 `上线前待办.md`。

## 三、顺带的安全加固

### 会话 Cookie 属性

```
Set-Cookie: session=...; HttpOnly; Path=/; SameSite=Lax
```

`SameSite=Lax` 让浏览器在**跨站发起 POST 时不携带会话 Cookie**，因此最常见的「恶意页面自动提交表单」型 CSRF 已经失效。这是对 DEF-002 的**部分缓解**。

仍未覆盖：同源场景下的伪造、`fetch`/XHR 跨站写请求，以及服务端缺少显式 token 校验（目前只是「浏览器恰好不送 Cookie」，属于依赖浏览器的被动防线）。

### 生产级 WSGI 服务器

新增 `SERVER=waitress`，可切到 Waitress。**Waitress 是可选依赖** —— 没装时自动回退 Flask 开发服务器并在日志里告警，不会因为缺一个可选包就起不来。

## 八、踩到并解决的坑

1. **`rm -rf` 也会被批量删除确认拦住**：`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] count:1123`。
   删 `dist/督办系统` 和 `build/督办系统` 都要**单独一条命令**。**不能和其他命令用 `&&` 串起来** ——
   一旦被拦整条链就断了，后面的 PyInstaller 根本没跑，但你会误以为它失败了。

2. **PyInstaller 会先删 `build/督办系统/base_library.zip`**，同样触发拦截。
   解法：先手动 `rm -rf build/督办系统`（等于全量重编，约 45 秒，可接受）。

3. **冒烟检查点选错**：`GET /login` 时会话为空，Flask **不下发** Set-Cookie。
   要验证 Cookie 属性必须在**登录 POST 之后**看响应头。

4. **构建脚本里有硬编码的文件数标签**：`print('03_开发代码/scripts: 1 个文件')` 在加了新脚本后会说谎，已改成按实际复制数输出。
