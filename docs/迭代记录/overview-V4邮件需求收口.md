# V4「发送邮件」功能需求收口

**日期**：2026-09-03
**产物**：`docs/督办系统-V4邮件功能需求清单.md`
**状态**：待用户最终拍板（C-1 / C-2 / C-3）

## 做了什么

通过 9 组主题（A–I）共 **55 个决策点**的苏格拉底式访谈，把「发送邮件」从一句话需求收敛成可开发的完整 SPEC。全程未写业务代码（遵守 SPEC 锁定前不动代码原则）。

## 关键调研发现

1. **`src/` 中零邮件代码** —— 无 smtplib、无 SMTP 配置、无发信记录表。
2. **`users` 表无 email 字段**（只有 username / display_name / password_hash / role / is_active / created_at）→ 本迭代必须做**数据库迁移**，是最难回头的改动，故优先提问。
3. **挂钩点干净**：预警只有两个出口（`_send_merged_warnings()` / `trigger_overdue_warning()`），最终都调 `models.create_message()`；已有去重函数 `has_warning_today()` 和配置表 `system_config`（`get_config`/`set_config`）→ 邮件配置可直接复用，队列可挂现有扫描循环，**零新增线程**。

## 核心决策（易忘的几条）

| 决策 | 内容 | 原因 |
|---|---|---|
| **B6 + C4** | 落库队列 + 每 5 分钟扫，复用 `scheduler.py` 现有循环 | 页面不卡顿、天然支持重试与限频、零新增线程 |
| **C2** | **不改** `models.create_message()`，只在预警引擎两出口挂钩 | 改它会把分配/状态变更/批示全变成邮件，淹没高价值低频消息 |
| **C6** | 邮件**独立去重键** | 共用会导致"未配邮件的沉默期吃掉去重名额"，配好 SMTP 当天反而发不出 |
| **F2 + D2** | 负责人多任务合并一封 + 管理员只收日报 | 邮件量从 500 封/天 压到 ~30 封/天，规避个人邮箱风控 |
| **G3** | 535 认证失败**立即熔断**整个邮件功能 | 否则一天 5760 次失败登录，可能把发件邮箱账号封停 |
| **G5** | 重启时"发送中"重置为"待发送" | "宁可重复、不可丢失"（用户已点头） |
| **B4 乙** | `pbkdf2_hmac` + `shake_256` XOR 加密，**零新依赖** | 避开 `cryptography` 的重打包成本；非 AES，已知局限已告知 |
| **I4** | `MAIL_ENABLED` 默认 `False` | 铁律「不配置 = 行为不变」，保护已发行的离线 exe |

## 用户接受的风险（需长期记住）

- 选用**个人邮箱 SMTP**：存在日发送限额风控、绑定在具体同事身上（离职即中断）、发件人形象差三项风险。代码层已做成**通用 SMTP 六字段抽象**，将来换企业邮箱**只改配置，零改码**。
- **乙方案加密非工业标准**，若将来过等保/安全审计，需换 `cryptography` 的 AES。
