# 改动待办清单

> 用法：发现页面哪里不对，往下面表格加一行就行。  
> 加的时候**不用写完整**——只写"哪里"和"想要什么"即可，细节我来补。

## 怎么往里加（三种任选，哪个顺手用哪个）

**方式一：直接跟我说一句话**（最省事）

> 例：「任务列表的优先级颜色看不清」「导出按钮点了没反应」

我会自动定位代码、改完、重启验证，然后回来把这条填进表格。

**方式二：截图 + 一句说明**（描述不清楚时最好用）

> 例：截一张图，说「这个位置间距太小」

**方式三：自己直接编辑本文件**（想攒一批时最方便）

> 在表格末尾加一行，日期、编号留空我来处理。

### 015 处理过程：任务列表分页改用 AJAX 原地刷新（014 锚点方案的修正）

**问题复现**：014 上线后，用户反馈「点下一页滚动条又跑到最下方」。  
定位根因：任务列表页表格**下方只有分页条 + 分页信息**，没有足够内容撑高页面。  
带 `#task-table` 锚点翻页时，浏览器想把表格顶到视口顶部，但下方空间不足，  
只能滚到**最大可用位置 = 页面底部** —— 于是「跳到底部」。  
（概览矩阵在 013 能用，是因为卡片下方还有别的看板内容撑住了高度，锚点能正常落位。）

**结论**：**整页跳转 + 锚点永远逃不开「顶 / 底」二选一的跳变**，锚点目标下方内容不够就必跳底。  
根治只能**不整页跳转**。

**改法**（彻底改方案，不再用锚点）：

- `static/js/main.js` 新增 `initPaginationAjax()`：仅当页面存在 `#batch-form`（任务列表页）时激活；  
  拦截 `.pagination a` 点击 → `fetch` 拉取新一页 → `DOMParser` 取出新 `#batch-form` →  
  `oldForm.innerHTML = newForm.innerHTML` 原地替换表格+分页+分页信息 →  
  `history.replaceState` 更新地址栏、**不触发滚动**。滚动条位置因此完全不变。
- 批量操作（`initBatchOps`）从「直接绑定子元素」改为**事件委托**（挂在 `document`，每次实时查 DOM），  
  这样分页刷新后新生成的行照样能勾选 / 全选 / 提交，监听器不会丢。
- `templates/tasks/list.html`：仅更新注释，分页链接保留 `#task-table` 作为**降级锚点**（JS 失效时退回整页跳转，且 fallback 会去掉 hash 避免又跳底）。

**验证**：`node --check` 语法通过；Flask 测试客户端 `admin/admin123` 登录后  
`/tasks?page=1` 正常渲染出 `#batch-form` / `.pagination` / `#task-table` / 下一页链接；  
6 个交付目标 diff 全 0；zip 回读 4 个关键文件逐字节一致；bat 仍 GBK+CRLF。

> 💡 **方法论沉淀**：凡是要「翻页但不让滚动条乱跳」，**优先 AJAX 原地刷新**，别依赖锚点。  
> 锚点只在「目标元素下方有足够内容」时才稳；列表页底部内容少，天然不适合。

### 013 处理过程：分页链接加锚点，翻页不再跳回顶部

**现象**：点「下一页」后，整个页面的滚动条回到最上方，看不到刚翻过的矩阵。

**根因：不是 bug，是浏览器默认行为。**  
分页链接原本是普通链接、不带锚点：

```html
<a href="/dashboard?range=all&mpage=2">下一页</a>
```

点击即触发**整页导航** → 加载新文档 → 浏览器滚动位置归零。  
排除了 JS 干扰（`main.js` 里没有 scroll / hash 相关处理）。

**改法**：给矩阵卡片加 `id="matrix-card"`，分页链接全部带上 `#matrix-card` 锚点。

```html
<div class="card" id="matrix-card">
<a href="{{ url_for('dashboard.overview', range=range_key, mpage=p) }}#matrix-card">{{ p }}</a>
```

**配套：sticky 顶栏的落位补偿。** 顶栏是 `position: sticky`、高 60px，  
不补偿的话锚点跳转后卡片顶部会被顶栏盖住：

```css
#matrix-card { scroll-margin-top: calc(var(--topbar-height) + 16px); }
```

`scroll-margin-top` **只在锚点定位时生效**，不影响正常布局 —— 这点很重要，  
不能改用 `margin-top`（那会真的把卡片往下推）。

**为什么不选另两个方案**：

- **AJAX 局部刷新**：改动大（要新接口 + 重渲染），当前整页跳转已经够快
- **JS 记住滚动位置再还原**：可行但更脆（要 sessionStorage + 时序处理），  
  且还原旧位置未必是用户想要的 —— 翻页后直接看到矩阵反而更自然

**验证**：矩阵卡片带 id；2 个分页链接均带锚点；`scroll-margin-top` 已下发；  
顶栏高度变量存在（60px + 16px = 76px 补偿）。改了模板，已重启服务。

### 012 处理过程：行高 56px + 表格区锁高（分页按钮固定）

**两个诉求**：行高调到 56px 减少留白；分页按钮位置也要固定，否则翻页时按钮乱跑。

**关键点：光固定行高解决不了按钮乱跑。**  
行高固定后，表格总高仍随行数变化（1 行 96px vs 8 行 488px），  
紧贴其后的分页按钮就会跟着上下移动。必须把**表格区高度也锁死**。

```css
.matrix-table tbody td { height: 56px; padding: 0 16px; vertical-align: middle; }
.dash-layout > .card .matrix-scroll { flex: 1 1 auto; min-height: 488px; }
```

488px = 表头 40 + 8 行 × 56，即「满页一张表」的高度。

**为什么不用 `margin-top: auto` 钉底**：钉底能让按钮贴卡片底部，  
但会在表格和按钮之间裂开一块随行数变化的空白 —— 按钮位置是稳了，空白却在动。  
锁表格区高度则让空白留在**表格区内部**（最后一行之下），  
按钮位置固定，而且空白被"框"在表格区的范围内，视觉上更像「这页人少」。

**翻页稳定性验算**（行高 56 / 表格区锁 488 / 焦点卡 644）：

| 行数 | 表格高 | 表格区 | 区内空白 |     卡片高 | 按钮 Y 偏移 |
| -: | --: | --: | ---: | ------: | ------: |
|  1 |  96 | 488 |  392 | **648** | **616** |
|  2 | 152 | 488 |  336 | **648** | **616** |
|  4 | 264 | 488 |  224 | **648** | **616** |
|  6 | 376 | 488 |  112 | **648** | **616** |
|  8 | 488 | 488 |    0 | **648** | **616** |

→ **行高、表格区、卡片高、按钮位置四项全部恒定**。

**56px 的取值依据**：自然行高约 45px；取 56px 是因为 8 行满页时  
40 + 8×56 = 488 正好填满表格区，底部几乎不留白（此前 48px 时 8 行只剩 424px，  
比 488 少 64px，那 64px 就成了底部留白 —— 用户看到的「最下方还是有空白」）。

**验证**：旧值 48px、旧 `flex: 0 1 auto` 均已清除；CSS 括号平衡；  
本轮**只改 CSS，未改模板**，无需重启。

### 011 处理过程：固定行高（取代 009 + 010 的拉伸方案）

**用户反馈**：「直接将每行的高度固定吧，要不翻页时高度来回变也不好看」。

**问题本质**：009 的拉伸方案是按比例把留白分给每行 ——  
8 行时每行 56px、6 行时 75px、3 行时会被拉到 150px+。  
**翻页时行数一变，行高就跟着变，视觉上在抖**。010 的行数阈值只是兜住了极端值，  
没解决抖动本身。固定行高才是根治。

**改法**：

```css
.matrix-table thead th { height: 40px; padding: 0 16px; }
.matrix-table tbody td { height: 48px; padding: 0 16px; vertical-align: middle; }
```

**写法要点**：用 `height` 锁定 + `padding: 0` + `vertical-align: middle`，  
**不能靠 padding 撑高** —— padding 撑出来的是「最小值」，内容一变就会被顶开，锁不住。

**数值依据**：自然行高约 45px（字号 14 × 行高 1.5 = 21 + 上下 padding 24），取 48px 略留余量。

**翻页稳定性验算**（行高固定 48px，焦点卡固定 644px）：

| 行数 | 表格高 | 矩阵卡 |   卡片最终高 | 底部留白 |
| -: | --: | --: | ------: | ---: |
|  1 |  88 | 248 | **644** |  396 |
|  3 | 184 | 344 | **644** |  300 |
|  5 | 280 | 440 | **644** |  204 |
|  8 | 424 | 584 | **644** |   60 |

→ **卡片高度恒定、行高恒定，只有底部留白随行数变化：翻页不抖。**

**配套清理**：

- 移除 `.matrix-fill` 相关的 3 条 CSS 规则（拉伸 / 表格满高 / 分页钉底）
- 移除模板里的 `matrix-fill` 条件类
- 分页改回全局的 `margin-top: 20px` **紧贴表格，不钉底**  
  —— 钉底的话，人少的页会在表格和分页之间裂开一大块空白
- 卡片仍是纵向 flex、两栏仍等高；焦点列表仍 `flex: 1 1 auto` 可伸缩

**验证**：页面已无 `matrix-fill`；8 行 × 20 条焦点正常渲染；CSS 9 项断言全通过。

### 010 处理过程：按行数开关矩阵拉伸（兜底）

**为什么 009 需要兜底**：拉伸的本质是把多余高度**平均分配给每一行**。  
行数越少，每行分到的越多 —— 8 行时每行约 56px（自然行高 44px，只是略透气），  
但只剩 1~2 行时，单行会被拉到几百像素高，比留白更难看。

**改法**：由模板按行数给卡片加开关类，CSS 只在开关存在时才拉伸。

```jinja
<div class="card {{ 'matrix-fill' if matrix|length >= 6 else '' }}">
```

| 行数 | 行为                       | 每行高度（约）                        |
| -: | ------------------------ | ------------------------------ |
| ≥6 | 拉伸，留白分配给各行；分页钉底          | 6 行 75px / 7 行 64px / 8 行 56px |
| <6 | 表格保持自然高度，留白落到卡片底部，分页紧贴表格 | 44px                           |

配套 CSS 调整：

```css
/* 默认不拉伸 */
.dash-layout > .card .matrix-scroll { flex: 0 1 auto; min-height: 0; }
/* 只有带开关的卡片才拉伸 */
.dash-layout > .card.matrix-fill .matrix-scroll { flex: 1 1 auto; }
.dash-layout > .card.matrix-fill .matrix-scroll .matrix-table { height: 100%; }
.dash-layout > .card.matrix-fill .pagination { margin-top: auto; padding-top: 20px; }
```

**阈值取 6 的依据**：可用空间约 448px（卡片 644 − chrome 108 − 分页 52 − 表头 36）。  
自然行高 44px，超过 80px 就明显发虚；6 行 = 75px 尚可，5 行 = 90px 偏高。

> 分页钉底也挂到同一个开关下了：不拉伸时分页紧贴表格，  
> 看起来像"这页人少"，而不是"内容被拽散"。

**验证**：当前演示数据 8 行 → 卡片带 `matrix-fill` → 走拉伸路径（与 009 效果一致）；  
推演 1~5 行走自然高度路径。CSS 括号平衡，旧的无条件规则已清理。

### 009 处理过程：矩阵表格跟随卡片一起拉伸

### 008 处理过程：顶栏对齐 + 双栏等高

**① 顶栏对齐（纯 CSS，未改模板、未重启）**

顶栏背景通栏铺满，但内部元素原来用固定 `padding: 0 24px`，贴着屏幕最边缘；  
正文却是「限宽 1600px 居中 + 32px 内边距」—— 两者左边缘对不上。

解法：给顶栏用**和正文一样的左偏移**当内边距，不动 DOM 结构：

```css
.topbar { padding: 0 max(32px, calc((100% - 1600px) / 2 + 32px)); }
```

|   视口 |                      公式值 |            正文左边缘 |  对齐 |
| ---: | -----------------------: | ---------------: | :-: |
| 1280 | max(32, −128) = **32px** |             32px |  ✅  |
| 1600 |   max(32, 32) = **32px** |             32px |  ✅  |
| 1920 | max(32, 192) = **192px** | 160 + 32 = 192px |  ✅  |
| 2560 | max(32, 512) = **512px** | 480 + 32 = 512px |  ✅  |

`100%` 按**父元素内容宽度**解析（已剔除滚动条），与内容区基准一致。  
≤768px 断点另有 `padding: 0 14px` 覆盖，与内容区的 14px 一致。

> 备选方案是给顶栏加一层 `.topbar-inner` wrapper（`max-width: 1600px; margin: 0 auto`），  
> 但要改模板 → 就得重启服务。上面这版纯 CSS 效果等价，**不用重启**。

**② 双栏等高**

`.dash-layout` 原为 `align-items: start`（各按内容高度）→ 两张卡底边对不齐。  
改回默认的 `stretch` 后等高了，但**较矮的一张底部会空出一截**（实测约 170px）。

所以卡片本身改成纵向 flex，让内容区吃掉多余高度、分页钉底：

```css
.dash-layout > .card { display: flex; flex-direction: column; }
.dash-layout > .card .focus-list,
.dash-layout > .card .matrix-scroll { flex: 1 1 auto; min-height: 0; }
.dash-layout > .card .pagination { margin-top: auto; padding-top: 20px; }
```

留白因此落在**表格与分页之间**（像有意的留白），而不是底部悬空一大块。

> ⚠️ **必须 `flex: 1 1 auto`，不能写 `flex: 1`**。  
> `flex: 1` 等价于 `flex: 1 1 0%`，basis 归零后卡片不再按内容撑高，  
> 焦点列表会被压矮、少显示好几条任务（20 条只剩几行可见）。  
> `1 1 auto` 保留内容高度作为基准，只在有多余空间时才增长。

**边界情况**：`<1280px` 断点下 `grid-template-columns: 1fr`，  
两张卡各占一行，stretch 不产生任何效果（行高 = 该卡内容高度），行为不变。

### 022 处理过程：翻页时两个模块高度不再齐变

**用户反馈**：「点击下一页两个模块的高度会变」。

**021 的残留问题**：021 给 `.matrix-scroll` 用了 `min-height: 280px + max-height: 380px`，  
而 `.dash-layout` 是 grid 且两卡 `align-items: stretch`（等高）。后果链：

- 矩阵某页行数少（<5 行）→ `.matrix-scroll` 被 `min-height:280` 撑到 280；
- 某页行数多（>6 行）→ 被 `max-height:380` 压到 380 内部滚；
- 右卡（含分页按钮）高度在「标题+280+分页」~「标题+380+分页」之间浮动；
- 左卡被 `stretch` 拉成等高 → **两个模块一起变高变矮**，翻页时肉眼可见跳变。

**022 改法**（只动 `static/css/main.css`，不动模板、不动功能）：

1. `.focus-list`：`max-height: 380px` → **`height: 380px`**（固定，不再随内容伸缩）。
2. `.dash-layout > .card .focus-list`：`flex: 1 1 auto; min-height: 0` → **`flex: 0 0 auto`**（不增长不收缩，锁死 380px）。
3. `.dash-layout > .card .matrix-scroll`：`flex: 1 1 auto; min-height: 280px; max-height: 380px` → **`flex: 0 0 auto; height: 380px; overflow-y: auto`**（去掉 min/max，固定高度）。

```css
.dash-layout > .card .focus-list { flex: 0 0 auto; }   /* 高度由 .focus-list{height:380px} 锁定 */
.dash-layout > .card .matrix-scroll {
    flex: 0 0 auto;   /* 固定，不随翻页行数伸缩 */
    height: 380px;
    overflow-y: auto;
}
.focus-list { height: 380px; overflow-y: auto; padding: 8px; margin: -8px; }
```

**效果**：无论本页几行，两个模块都恒为 380px，卡片高度恒定；翻页时唯一变化的是「模块内部是否出现/消失滚动条」，卡片框和分页按钮位置都不再跳。两卡因 `stretch` 仍严格等高。`flex: 0 0 auto` 替代 021 的 `flex:1 1 auto`，正是 022 与 021 的关键差异（021 允许伸缩 → 高度浮动）。

**同步**：`main.css` cp 到 5 处副本，diff 全 0；运行服务已 `Ctrl+F5` 前下发新规则（已用 urllib 抓取 `/static/css/main.css` 校验 3 项全中）。纯 CSS，浏览器强刷即生效。

### 005 处理过程：焦点列表 hover 效果被裁

**根因**：`.focus-list` 为滚动容器（`overflow-y: auto`）。按 CSS 规范，**一个轴设为 `auto` 时另一个轴的 `visible` 会被强制计算成 `auto`** —— 所以不只是纵向，横向也在裁切。

hover 时 `.focus-item` 做了两件会"溢出自身盒子"的事：

| 效果                                             | 向上溢出量       | 左右溢出量 |
| ---------------------------------------------- | ----------- | ----- |
| `transform: translateY(-1px)`                  | 1px         | —     |
| `box-shadow: 0 4px 12px`（blur 12 / offset-y 4） | 6 − 4 = 2px | 各 6px |

合计**顶部溢出约 3px**，正好被滚动容器的上边缘切掉 —— 只有第一个条目能看出来，因为它上方没有别的条目挡着。

**修法**：给滚动容器留 8px 呼吸位，再用负 margin 把视觉位置拉回原处。

```css
.focus-list {
    max-height: 536px;   /* 520 + 上下 padding 16，可见内容高度不变 */
    overflow-y: auto;
    padding: 8px;        /* 预留阴影 / 位移空间 */
    margin: -8px;        /* 抵消留白，列表视觉位置与改前一致 */
```
