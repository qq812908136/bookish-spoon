# 督办系统 — 邮件功能配置指南

> **适用版本**：V4
> **读者**：系统管理员（不看代码也能照着配完）
> **相关文档**：需求与决策依据见 `督办系统-V4邮件功能需求清单.md`；代码级实现见 `architecture-design.md`
>
> **一句话**：邮件是**站内信之外的第二通道**。配好了任务提醒会多一路触达；**不配或配错了，系统照常运转**，只是回到 V3 那样只发站内信——不会丢数据、不会影响任务流转。

---

## 一、先搞清楚三件事

| 问题 | 结论 |
|---|---|
| **不配会怎样？** | 一封邮件都不发，所有提醒只走站内信。业务功能完全不受影响。 |
| **配错了会怎样？** | 邮件进「失败清单」，管理员在「邮件」页一眼可见，可一键重发。**不会**反复重试把邮箱搞封号（有熔断保护，见第七节）。 |
| **要花钱吗？** | 不用。用组织已有的一个普通邮箱（QQ / 163 / 企业邮箱都行）作为发件箱即可，走它的免费 SMTP 额度。 |

---

## 二、5 分钟上手

### 第 1 步：准备一个发件邮箱

建议**专门申请一个**（如 `duban@公司域名.com` 或 `通知专用@qq.com`），不要直接用个人日常邮箱：

- 发件人会显示在所有收件人眼前，用个人邮箱不够正式；
- 邮件全走这一个账号，出问题只影响它自己；
- 万一账号被风控，不影响任何人的日常邮件。

拿到邮箱后，去邮箱设置里**开启 SMTP 服务**，并拿到**授权码**（一串 16 位左右的字母）。

> ⚠️ **绝大多数配置失败都栽在这一步**：填的是**邮箱登录密码**而不是**授权码**。
> 现在的主流邮箱（QQ、163、 Gmail、企业微信邮箱）在第三方客户端登录时都要求用独立的「授权码 / 应用专用密码」，登录密码会被直接拒绝（错误码 535）。

### 第 2 步：在系统里填配置

用**管理员**账号登录，顶部导航点击 **「邮件」**（只有管理员能看到这个入口）：

1. 勾选 **「启用邮件通知」**
2. 填 **SMTP 服务器**、**端口**
3. 加密方式选 **SSL（465）** 或 **STARTTLS（587）**，**二选一**
4. 填 **账号（发件邮箱）** 与 **SMTP 密码 / 授权码**
5. **发件箱地址**通常与账号一致
6. 点 **「保存配置」**

### 第 3 步：用测试邮件验证

同一页的「验证与运维」卡片里，选一个收件人，点 **「发送测试邮件」**。

> 测试邮件**不走队列**，点了就立刻连接 SMTP，是最快的校验方式。
> 收不到？直接看页面提示：它会把 SMTP 服务器的原话（比如 `535 authentication failed`）翻成中文告诉你，不用去翻日志。

### 第 4 步：让用户有邮箱可收

「邮件」页会列出**还没填邮箱的用户**。两条路：

- **管理员代填**：在名单里直接补（用户自己也能在「个人设置 → 邮件通知」里查到并修改）；
- **用户自填**：各人登录后在「个人设置 → 邮件通知」里填自己的邮箱、选订阅等级。

### 常见邮箱的 SMTP 参数

| 服务商 | SMTP 服务器 | SSL 端口 | STARTTLS 端口 | 密码填什么 |
|---|---|---|---|---|
| QQ 邮箱 | `smtp.qq.com` | 465 | 587 | **授权码**（设置 → 账户 → 开启 IMAP/SMTP 后生成） |
| 163 邮箱 | `smtp.163.com` | 465 | 994 | **授权码**（设置 → POP3/SMTP/IMAP → 新增授权密码） |
| Gmail | `smtp.gmail.com` | 465 | 587 | **应用专用密码**（需先开启两步验证） |
| 腾讯企业邮箱 | `smtp.exmail.qq.com` | 465 | 587 | 邮箱密码或客户端专用密码（视管理员设置） |
| 阿里企业邮箱 | `smtp.qiye.aliyun.com` | 465 | 587 | 邮箱密码（需在后台开启 SMTP） |
| Outlook / 365 | `smtp.office365.com` | — | 587 | 邮箱密码（可能需管理员开启 SMTP AUTH） |

> 端口和加密方式**必须配套**：465 配 SSL，587 配 STARTTLS。填反了会连不上或超时。

## 三、谁会收到什么邮件

### 触发场景

| 场景 | 触发时机 | 收件人 | 频率控制 |
|---|---|---|---|
| **任务分配通知** | 新建任务指派负责人、或改派给他人 | 新负责人 | 同一任务同一天只发一次 |
| **逾期提醒** | 任务变为「已逾期」，及后续周期性提醒 | 负责人 | 逾期第 1/2/3 天各一封，之后**每 3 天**一封 |
| **即将到期提醒** | 距截止日期 ≤ 3 天 | 负责人 | 每个任务每天最多一封 |
| **长期待激活提醒** | 任务创建后 7 天仍是「待启动」 | 负责人 | 每个任务每天最多一封 |
| **管理员日报** | 每日 09:00 预警扫描 | **仅管理员** | 每天一封汇总 |
| **手动提醒** | 管理员/创建人在任务里点「发送提醒邮件」 | 该任务负责人 | 同一人对同一任务 **5 分钟冷却** |

### 用户能自己选收多少（订阅等级）

在「个人设置 → 邮件通知」里，每人可选：

| 等级 | 会收到 | 适合谁 |
|---|---|---|
| **不接收邮件提醒** | 一封都不发，包括任务分配通知 | 只看站内信的人 |
| **仅逾期（推荐，默认）** | 逾期提醒 + 任务分配通知 | 大多数人 |
| **逾期 + 即将到期** | 上面两项 + 即将到期提醒 | 想提前准备的人 |
| **全部预警** | 再加长期待激活提醒 | 任务多、怕漏的人 |

> **注意**：订阅等级管的是**预警类**邮件。「任务分配通知」在你不是「不接收」时都会发——任务分到你头上了却不知道，是最不能接受的一种漏。
>
> 📌 上表里的「距截止 ≤ 3 天」「创建后 7 天」这两个阈值来自**系统设置**里的预警参数，不是邮件专属配置，改了会同时影响站内信。

## 四、为什么一天只有几十封？

任务多的时候，最怕邮箱被提醒邮件淹掉。系统做了三层收敛：

1. **按人合并**：同一个人名下有 5 个逾期任务 → **只发 1 封**，正文里列出 5 条，不是 5 封。
2. **管理员只收日报**：管理员**不会**收到其他负责人任务的零散邮件——全组织的逾期情况合并成每天 09:00 的一封汇总日报发给他们。（管理员如果自己也是某任务的负责人，那封按人合并的提醒照发，因为那对他来说是「我的任务」。）
3. **每轮限量**：一个发送周期最多发 `batch_limit`（默认 20）封，剩下的留到下一轮（5 分钟后）。

实测对比：500 个任务、50 个负责人的规模下，从「500+ 封/天」降到「约 30 封/天」。

## 五、配置项逐项说明

### 基础

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用邮件通知 | **关** | 总开关。关着的时候其他配置填了也不发 |
| SMTP 服务器 | 空 | 见上表 |
| 端口 | 465 | 1–65535；465 = SSL，587 = STARTTLS |
| 账号（发件邮箱） | 空 | 多数邮箱要求与发件箱地址一致 |
| SMTP 密码 / 授权码 | 空 | **加密入库**，页面上永远显示为占位符，且不会写进日志。留空 = 不修改原密码 |
| 加密方式 | SSL | SSL 与 STARTTLS **二选一**，都不选 = 明文连接（不建议） |
| 发件箱地址 | 空 | 收件人看到的「来自」地址 |
| 发件人名称 | 督办系统 | 收件人看到的显示名 |
| 邮件尾部说明 | 本邮件由督办系统自动发送，请勿直接回复。 | 每封邮件末尾固定附一段 |

### 发送策略

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 单轮发送上限 | 20 封 | 每 5 分钟一轮，超出留到下一轮。防止瞬间大量外发被服务商风控 |
| 失败重试次数 | 3 次 | 重试间隔按 **5 → 15 → 30 分钟**递增（指数退避） |
| 手动发送冷却 | 300 秒 | 同一人对同一任务多久内不能重复点「发送提醒邮件」 |

### 隐私

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 邮件标题中隐去任务标题 | 关 | 打开后标题只显示「任务 #12」这类编号。适合收件人的邮箱会被同事/领导看到的场景 |

## 六、邮件页能看什么

管理员进「邮件」页，从上到下依次是：

1. **状态横幅**（不可关闭）——未配置或已熔断时，页面最顶部会有红条说明原因。这是刻意设计的：**「邮件悄悄不发了」是最难发现的故障**，不能让它只存在于日志里。
2. **今日概览**——今日成功 / 今日失败 / 队列中待发 / 最近一次成功时间。
3. **熔断详情**（仅熔断时出现）——原因、熔断时间、何时恢复、连续失败次数，附「修正后恢复发送」按钮。
4. **SMTP 配置**——就是第二节填的那张表。
5. **验证与运维**——发测试邮件、立即发送队列（不想等下一个 5 分钟时用）。
6. **未填邮箱名单**——谁收不到邮件，可以直接代填。
7. **发送失败清单**——失败原因 + 一键重发。
8. **发送记录**——可按结果 / 类型 / 关键字筛选，分页，保留 90 天。

普通用户没有「邮件」页，他们在「个人设置 → 邮件通知」里改自己的邮箱和订阅等级，并通过 **「查看我的邮件记录」** 看发给自己的邮件历史（看不到别人的）。

## 七、发不出去时怎么办

### 先看错误类型

| 页面提示 | 含义 | 怎么处理 |
|---|---|---|
| `535` / 认证失败 | **授权码填错**，或在服务商处没开 SMTP | 重新生成授权码填上。**这类错误会立即熔断**（见下） |
| `550` / 收件人不存在 | 对方邮箱地址写错了 | 修正该用户邮箱后重发 |
| 被判定为垃圾邮件 | 内容或发件频率触发风控 | 降低发送频率（调小单轮上限），或换发件邮箱 |
| 连接超时 / 拒绝连接 | 服务器地址或端口填错 | 对照第二节的参数表核对 |
| 发送过于频繁（限流） | 服务商临时限流 | 不用管，系统会自动重试（5/15/30 分钟） |

### 熔断机制（为什么不会把邮箱搞封号）

系统有两道闸，任何一道触发都会**暂停发送**：

| 类型 | 触发条件 | 恢复方式 |
|---|---|---|
| **认证失败熔断** | 出现一次账号/密码类错误 | **立即熔断，必须人工恢复**。修好配置后在「邮件」页点「修正后恢复发送」 |
| **连续失败熔断** | 连续失败 10 封（默认） | 暂停 60 分钟后**自动试探**一次，成功即恢复 |

> 为什么认证失败要人工介入？——用错误的密码反复重试，一天能试出几千次失败登录，绝大多数邮箱服务商会**直接封号**。宁可让管理员点一下按钮，也不能冒这个风险。

### 手动重发

失败清单里每条记录后面都有 **「重发」** 按钮，改完邮箱或修好配置后点它即可。已发送成功的记录不允许重发（避免重复骚扰收件人）。

## 八、隐私与安全

| 措施 | 说明 |
|---|---|
| **密码加密存储** | SMTP 授权码加密后入库，页面上永远只显示占位符，**不写进任何日志** |
| **邮箱可见范围** | 用户的邮箱只有**本人**和**管理员**能看到；用户列表页**不显示邮箱列**；管理员在「邮件」页看到的是「谁还没填」，不是所有人的地址清单 |
| **标题可脱敏** | 开启后邮件标题不出现任务标题，只留编号 |
| **日志只记元数据** | 记「发给了谁、什么类型、成功与否」，**不记邮件正文** |
| **默认关闭** | 不配置就一封不发，不存在「装上了就在偷偷发信」 |

## 九、环境变量（可选，一般不用）

全部邮件配置都能在页面上填。**只有当**你需要「配置不进数据库」（如无人值守部署、多机共用一套发件账号）时，才写在 `.env` 里。

优先级：**环境变量 > `.env` > 页面上保存的值 > 代码默认值**。

被环境变量占住的配置项，页面上会标注「已被环境变量锁定」——**这不是保存失败**，是提醒你改页面的值不会生效。

完整清单见仓库根目录 `.env.example` 的「邮件通知（V4）」段。最常用几项：

```
MAIL_ENABLED=true
MAIL_SMTP_HOST=smtp.qq.com
MAIL_SMTP_PORT=465
MAIL_USE_SSL=true
MAIL_SMTP_USERNAME=notice@example.com
MAIL_SMTP_PASSWORD=你的授权码        # ⚠️ 明文，仅在确有必要
MAIL_FROM_ADDR=notice@example.com
```

> ⚠️ 把授权码写进 `.env` 意味着**任何能读取该文件的人都能看到明文**。页面填写会加密入库，通常更安全。

## 十、常见问题

**Q：配好了，但没人收到邮件。**
A：按这个顺序查：① 总开关勾了吗；② 用户填邮箱了吗（看「未填邮箱名单」）；③ 用户订阅等级是不是「不接收」；④ 发测试邮件能通过吗；⑤ 页面顶部有没有熔断红条。

**Q：测试邮件成功，但自动提醒不发。**
A：自动提醒是**入队后由后台 5 分钟一轮**发送的，不是实时的。可以点「立即发送队列」跳过等待。另外检查用户订阅等级是否过滤掉了该类型。

**Q：同一个人收到好几封一样的。**
A：去重是按「类型 + 任务 + 日期」做的，正常不会重复。重复的话多半是手动点了多次「发送提醒邮件」——手动邮件有 5 分钟冷却，但换个人点不算同一人。

**Q：换发件邮箱了，要改哪些地方？**
A：只改「邮件」页的 SMTP 配置即可，密码框留空表示不改。改完务必发一封测试邮件验证；如果之前因认证失败熔断过，记得点「修正后恢复发送」。

**Q：`data/secret.key` 是什么？丢了会怎样？**
A：它是本地加密用的密钥文件，**SMTP 授权码靠它加密**。丢了之后已存的授权码**无法解密**，需要重新填一次密码（其他数据不受影响）。备份时请连同 `data/` 一起备份。

## 十一、管理员自查清单

配置完成后走一遍：

- [ ] 「邮件」页顶部**没有**红色横幅
- [ ] 状态徽标显示 **「已启用」**
- [ ] 测试邮件**收到**了，且发件人显示正确
- [ ] 「未填邮箱名单」为空，或剩下的人确实不需要收邮件
- [ ] 订阅等级按团队习惯确认过（默认「仅逾期」）
- [ ] 确认过一次**自动**邮件能到（不只是测试邮件）
- [ ] 已把 `data/` 目录纳入备份（含 `secret.key`）
