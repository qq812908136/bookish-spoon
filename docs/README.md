## 一、为什么这里有两套命名？

`docs/` 里同时存在英文短名（如 `iteration-v2-design.md`）和中文长名（如 `督办系统-接口设计.md`），这是历史原因，**不是整理遗漏**：

| 命名风格 | 来源 | 代表文件 |
|---|---|---|
| **英文短名** | V1/V2 开发期按文件名手写引用，散落在 PRD、待办清单、CSS 注释里 | `architecture-design.md`、`iteration-v2-design.md`、`iteration-v2-diff-analysis.md` |
| **中文长名** | 交付包 `02_设计文档/` 的对外正式名，便于客户阅读 | `督办系统-接口设计.md`、`督办系统-数据库设计.md`、`督办系统-模块详细设计.md`、`督办系统-系统架构设计.md` |

**切换成本**：英文短名的 3 份已被 7 处引用（`docs/改动待办清单.md:379/380/381/439`、`docs/PRD-draft-v1.md:541/705`、`src/static/css/main.css:4`），改名会同时断掉这些引用，因此**保留英文短名不动**。

**今后约定**：新文档一律用**中文长名**（与交付包官方名一致），英文短名仅作为历史别名保留，不再新增。

## 二、两份「架构」文档不是重复，是互补

这是最容易误判的一点。名字都带「架构」，但**内容完全不同**：

| | `architecture-design.md` | `督办系统-系统架构设计.md` |
|---|---|---|
| **定位** | **代码级架构手册**——照着它能改代码 | **架构决策文档**——照着它能理解为什么这么选 |
| **章节** | 一、系统架构概览<br>二、目录结构<br>三、数据库设计<br>四、Flask 路由与 API<br>五、状态机实现<br>六、预警系统<br>七、权限控制<br>八、依赖包列表 | 1. 技术栈选型<br>2. 分层架构<br>3. 模块划分图<br>4. 部署架构<br>5. 启动流程<br>6. 线程模型<br>7. 设计决策与权衡<br>8. V2 架构增补 |
| **回答的问题** | 「这个表有哪些字段？这个路由做什么？状态怎么流转？」 | 「为什么选 Flask 不选 Django？为什么用 SQLite？线程怎么开的？权衡过什么？」 |
| **典型读者** | 开发工程师（改代码前查它） | 新接手的人、评审者、运维（理解全貌时看它） |
| **体积** | 76789 字节（细） | 27251 字节（精炼） |

**结论：两份都保留，不要合并、不要删。** 若只有一份，改代码的人会缺细节，看全貌的人会被细节淹没。

## 五、维护约定

1. **改文档只改 `docs/`**，改完执行 `python scripts/build_delivery_package.py v4` 同步到交付包。
2. **交付包副本禁止手改** —— 下次同步会被覆盖。
3. **v1/v2/v3 交付包不可重建** —— 脚本内置 `REBUILDABLE` 白名单闸门，仅允许 `v4`–`v9` / `test`。
4. **新增文档用中文长名**，并回到本索引的「文档地图」补一行。
