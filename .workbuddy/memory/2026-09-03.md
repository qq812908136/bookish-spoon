## V4「发送邮件」功能需求访谈 A–I 全程收口（00:00–00:45）

**背景**：用户要求以苏格拉底式「按主题分组、每组连续追问、高影响约束优先」的方式，把新增「发送邮件」功能从一句话需求引导成完整 SPEC。9 组共 55 个决策点，全程未写业务代码。

### 前置调研发现（决定提问顺序）
- `src/` **零邮件代码**：无 smtplib、无 SMTP 配置、无发信记录表。
- **`users` 表无 email 字段**（仅 username/display_name/password_hash/role/is_active/created_at）→ 必须做**数据库迁移**，是本次最难回头的改动，故列为 A5 优先提问。
- **挂钩点干净**：预警仅两个出口 `_send_merged_warnings()` / `trigger_overdue_warning()`，最终都调 `models.create_message()`；已有 `has_warning_today()` 去重函数与 `system_config` 表（`get_config`/`set_config`）→ **邮件配置复用现有配置表，队列挂现有 scheduler 循环，零新增线程、零新建配置表**。

### 最终决策（详见 `docs/督办系统-V4邮件功能需求清单.md`）
- **A 目标边界**：A1-①提醒到人｜A2-①可用即可｜A3-②排除「邮件内审批」｜A4-②自动+手动｜A5-②`email` 选填降级站内信。
- **B 服务商**：B1-②个人邮箱 SMTP + **采纳建议做成通用 SMTP 六字段抽象**（换企业邮箱零改码）｜B2-③共用发件箱 + `Reply-To` 指向操作人｜B3 `.env` 默认 + 设置页加密覆盖｜**B4-乙**：`hashlib.pbkdf2_hmac` 从 `data/secret.key` 派生 32B 密钥 + `shake_256` 密钥流 XOR，**零新依赖、不用重打包**（非 AES，已告知局限）｜B5-①静默降级 + ②设置页红条｜B6-③落库队列 + 定时扫描。
- **C 触发耦合**：C1-③默认仅逾期 + ④可订阅升级｜**C2-②只在预警引擎两出口挂钩，绝不改 `models.create_message()`**（否则分配/状态变更/批示全变邮件）｜C3-①任务详情页按钮｜C4-②每 5 分钟复用现有循环｜C5-①分配/改派通知新负责人（闭环/撤销不发）｜**C6-②邮件独立去重键**（共用会导致「未配邮件的沉默期吃掉去重名额」，配好 SMTP 当天反发不出）。
- **D 收件人**：D1-①负责人+在职管理员｜D2-②管理员只收每日汇总｜D3-①每人单发不用 CC｜D4-②跳过+状态页显示未填邮箱名单｜D5-①只发系统内用户｜D6-②四级订阅（`off`/`overdue`默认/`overdue_due`/`all`，字段 `users.mail_notify_level`）。
- **E 模板**：E1-①`[督办系统] 任务逾期提醒：{标题}`（超 20 字截断）｜E2-①精简正文｜**E3-②不放链接 → 无需 `SITE_URL` 配置项**｜E4-①固定模板+落款可配｜E5-①`MAIL_FOOTER`｜E6-②日报按负责人分组。正文统一纯文本 text/plain + UTF-8。
- **F 频率**：F1 逾期 1/2/3 天每天、之后每 3 天｜F2-②同负责人合并一封｜F3-②每轮最多 20 封｜F4-②手动 5 分钟冷却｜F5-①无总次数上限。→ **邮件量 500封/天 压到 ~30封/天**。
- **G 失败重试**：G1-①重试 3 次（5/15/30 分钟）｜G2 按错误码分类｜**G3-③认证失败立即熔断整个邮件功能**（否则 5760 次/天失败登录会被服务商封号）｜G4-②连续失败 10 次暂停 60 分钟｜G5-①重启时 `sending`→`pending`（**「宁可重复不可丢失」已获用户点头**）｜G6-①已生成的继续发、不追溯补生成｜G7-①失败清单+一键重发。
- **H 权限安全**：H1-②管理员+任务创建人｜H2-①管理员看全部、用户只看「发给我的」｜**H3-①邮箱仅本人+管理员可见，用户列表页不显示邮箱列**｜H4-②可附 ≤200 字纯文本留言｜H5-②`MAIL_MASK_TITLE` 脱敏开关默认关｜H6-①发信记录加操作人字段做审计。
- **I 日志配置**：I1-①②③④全选（含**发送测试邮件按钮**，否则排查周期被拉长一天）｜I2-②保留 90 天（挂现有循环，一天判断一次）｜I3-①**只记元数据不记正文，SMTP 密码任何情况不入日志（硬约束）**｜I4-①`MAIL_ENABLED` 默认 `False`（铁律「不配置=行为不变」）｜I5 确认数据模型｜I6-①单独出《邮件功能配置指南》+ ③更新 CHANGELOG。

### 本轮修掉的真实 bug
1. **`save_config` 漏传密码**：路由组装 `data` 时没放 `smtp_password`，导致授权码永远存不进去（页面显示保存成功，实际每次重填都丢）。修复：把 `new_pwd` 写进 `data`，`save_password=bool(new_pwd)` 保留「留空不改」语义。
2. **整页提交返回一屏 JSON**：`/tasks/<id>/send-mail` 原本只 `jsonify`。新增 `_mail_result()` 按 `is_json` / `X-Requested-With` 自适应（AJAX→JSON，整页→flash+重定向）。
3. **`get_mail_config()` 打 14 条 SQL**：抽屉每开一次付 14 次查询。改为 `get_all_config()` 一次读出后内存比对。

### 三个反复踩到的测试写法坑（通用）
- **模拟复选框未勾选必须删键**：路由判断 `'enabled' in form`（键存在即为真），传 `enabled=''` 键仍在 → 测不出取消勾选。测试辅助函数需支持 `None` = 删除该键。
- **模板 if/elif 分支会让断言落空**：熔断横幅是 `{% if not configured %}...{% elif circuit.state=='open' %}`，未先配置邮件就断言熔断横幅必然失败。先造好前置状态再断言。
- **页面里同名内容会污染 `assertNotIn`**：失败邮件无论怎么筛都显示在独立的「发送失败清单」卡里，用「主题是否出现」判断筛选是否生效永远为真。改用卡片标题里的「共 N 条」计数断言。

### SPEC 与实现的两处口径确认（已回写 SPEC 第 9 章）
1. **R-1 vs R-2 张力**：R-1「预警收件人=负责人+在职管理员」与 R-2「管理员只收日报」合并理解为——管理员**不收他人任务的零散邮件**（并入 09:00 日报），但若本人是某任务负责人，那封按人合并的提醒照发。代码未额外抑制管理员，按此实现。
2. **保存配置不自动解除熔断**：认证失败熔断后，改好配置仍需点「修正后恢复发送」。刻意如此——熔断时页面上显示的大概率就是错误密码，自动恢复会让「改了没生效」更难排查。
