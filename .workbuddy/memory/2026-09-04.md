## 多实例切换导致 CSRF 400（用户改密码遇到，非 bug）
- 现象：用户改密码提交 → 400「安全令牌无效或已过期」。改密码表单 `settings/profile.html` 第 13 行确认带 `csrf_token`，排除漏令牌 bug。
- 根因：当天本机起过 3 个实例（`dist/` exe 07:58、交付包 `05_离线程序` exe 08:11/08:27、源码 08:18），都监听 127.0.0.1:5000。**每个实例有独立 `data/secret.key`，而浏览器 Cookie 只按 host:port 区分** → 切实例后旧会话/旧页面令牌全部失效。另一常见触发：另一个标签页重新登录（登录走 `rotate_csrf_token()` 轮换会话密钥，旧页面令牌作废，属安全设计）。
- 解法：返回上一步 → 刷新页面 → 重填提交。令牌默认 24h 有效，「页面开太久」反而不是主因。
- **演示注意**：评审/演示前务必只保留一个实例运行，切换实例后先刷新或重新登录，避免现场踩到同样的 400。

## 重置密码 400 真 bug 修复（已交付）
- 根因：`users/manage.html` 重置密码表单 onsubmit 用裸 `querySelector('input')` 取「第一个 input」填新密码；DEF-002 加的 `csrf_token` 隐藏框排在 `new_password` 之前 → JS 把新密码写进令牌字段，浏览器端必报「安全令牌无效或已过期」。测试客户端不执行 JS 故 181 项全过也未暴露。
- 修复：改按 `input[name=new_password]` 选择；新增守护用例 `test_no_bare_input_queryselector_in_templates`（全局禁裸选择器）；全模板排查仅此一处。
- 连带发现：测试套件会被开发机 `.env`（`AI_ENABLED=true`）串扰致 2 用例误失败 → test_suite.py 头部预置 `os.environ['AI_ENABLED']='false'` 隔离（`_load_dotenv` 只补缺失键）。
- 验证：TestCSRF 17/17；exe 冒烟（/login→登录→/users 渲染含修复）；全量 **182/182 通过**。
- 交付：重打包 exe（10:23）→ 重建 v4 交付包（274 条目/13.9MB，zip 复核全过：testzip 干净、secret.key=0、仅内置演示库、15 bat GBK+CRLF、含修复）；用户演示机部署只需替换 exe+`_internal/`，**保留演示机 `data/`**。
