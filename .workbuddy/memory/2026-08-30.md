## 改动 005：焦点列表 hover 效果被裁（CSS overflow 经典坑）

### 现象
「今日督办焦点」模块鼠标悬停**第一个**任务时，高亮边框 + 阴影的**上方显示不全**。

### 根因（CSS 规范细节，值得记住）
`.focus-list` 是滚动容器（`overflow-y: auto`）。按 CSS Overflow 规范：
**一个轴设为 `auto`/`scroll` 时，另一个轴的 `visible` 会被强制计算成 `auto`**
→ 不只是纵向，**横向也在裁切**（代码里只写了 `overflow-y`，实际两轴都裁）。

hover 时 `.focus-item` 有两处"溢出自身盒子"的效果：
- `transform: translateY(-1px)` → 向上 1px
- `box-shadow: 0 4px 12px` → 向上 `blur/2 - offsetY` = 6−4 = **2px**，左右各 **6px**

顶部合计溢出约 3px 被切掉；只有第一个条目看得出来，因为它上方没有相邻条目遮掩。

### 修法（通用套路：留白 + 负 margin 抵消）
```css
.focus-list {
    max-height: 536px;   /* 520 + 上下 padding 16，可见内容高度不变 */
    overflow-y: auto;
    padding: 8px;        /* 为阴影/位移预留空间 */
    margin: -8px;        /* 抵消留白，列表视觉位置与改前一致 */
}
```
依据是 `overflow` 裁切发生在 **padding box 边缘**（不是 content box），
padding 属于"可显示区"，负 margin 把盒子拉回原位 → 位置不变但有了余量。
（注：全局 `* { box-sizing: border-box }`，所以 max-height 要 +16 补偿 padding）

### 排查同类问题的口诀
看到"hover/选中效果显示不全" → 先查祖先链上有没有 `overflow: hidden/auto`
→ 再算 `transform` 位移 + `box-shadow` 的 blur/2 ± offset 溢出量 → 用 padding 留够。

## 改动 008：顶栏对齐 + 双栏等高

### ① 顶栏与正文左对齐（纯 CSS，不动模板）
顶栏背景通栏、内部 `padding: 0 24px` 贴屏幕边缘；正文是「限宽 1600 居中 + 32px 内边距」，
左边缘对不上。解法：顶栏用**和正文相同的左偏移**当内边距，不加 wrapper：

```css
.topbar { padding: 0 max(32px, calc((100% - 1600px) / 2 + 32px)); }
```

**关键知识点**：CSS 百分比 **padding 是按「父元素内容宽度」解析的**（不是元素自身宽度），
且已剔除滚动条 —— 所以与 `.main-content` 的居中基准天然一致，不会差那 15px。
`max(32px, ...)` 保证视口 <1600px 时退化为 32px，与内容区内边距相同。

> 备选是加一层 `.topbar-inner` wrapper（max-width + margin auto），
> 效果等价但要改模板 → 得重启服务。纯 CSS 版不用重启，优先选。

### ② 双栏等高（flex basis 陷阱）
`.dash-layout` 原 `align-items: start` → 两卡底边不齐。改默认 `stretch` 后等高，
但**较矮的一张底部空出约 170px**。于是卡片改纵向 flex：

```css
.dash-layout > .card { display: flex; flex-direction: column; }
.dash-layout > .card .focus-list,
.dash-layout > .card .matrix-scroll { flex: 1 1 auto; min-height: 0; }
.dash-layout > .card .pagination { margin-top: auto; padding-top: 20px; }
```
留白落在「表格与分页之间」（像有意留白），分页钉底，不悬空。

> ⚠️ **必须 `flex: 1 1 auto`，绝不能写 `flex: 1`**。
> `flex: 1` = `1 1 0%`，basis 归零后卡片不再按内容撑高，
> 焦点列表会被压矮、20 条任务只剩几行可见 —— 静默的功能退化。

## 改动 009：矩阵表格跟随等高拉伸（008 的返工）

### 现象

两栏等高必然导致"矮的那栏多出来的空间"。处理方式三选一：
1. 让内部内容区 flex:1 自动填充（本案焦点列表已 capped，无法更多填充）
2. 让表格/列表本身 height:100% 把空间分配给行（本案采用）

## 改动 010：矩阵拉伸按行数开关（009 的兜底）

### 为什么纯 CSS 兜不住
拉伸的本质是把多余高度**平均分配给每行** → 行数越少每行分到越多。
8 行时每行 56px（自然行高 44px，略透气，好看）；1~2 行时单行 400px+，灾难。

**`max-height` 救不了**：给 `.matrix-scroll` 加 max-height 只是把"行太高"
换成"表格下方又出现死区"，而且阈值不随行数变化，8 行和 1 行用同一个值必然顾此失彼。
→ **需要"行数感知"，CSS 做不到，只能由模板按数据加开关类。**

### 解法
模板：`class="card {{ 'matrix-fill' if matrix|length >= 6 else '' }}"`
CSS：默认 `flex: 0 1 auto`（不拉伸），只有 `.matrix-fill` 才 `flex: 1 1 auto` +
表格 `height: 100%` + 分页 `margin-top: auto` 钉底。

阈值 6 的依据：可用空间约 448px（卡片 644 − chrome 108 − 分页 52 − 表头 36）。
6 行 75px / 7 行 64px / 8 行 56px 尚可；5 行 90px 就发虚。

### 通用模式（值得记住）
**"把多余空间分配给 N 个条目"这类 CSS，必须考虑 N 很小的情况。**
纯 CSS 无法感知 N，要么：
1. 由模板按 N 加开关类（本案采用，精确）
2. 放弃分配，接受留白（兜底行为）
不要指望 `max-height` 能解决——它只是把问题换个位置。

## 改动 012：行高 56px + 表格区锁高 488px

### 用户两个诉求
1. 行高 48px 底部仍留白 → 调到 56px
2. 「翻页按钮会乱跑」→ 位置要固定

### 关键洞察：光固定行高解决不了按钮乱跑
011 只固定了行高，但**表格总高仍随行数变化**（1 行 96px vs 8 行 488px），
紧贴其后的分页按钮就会跟着上下移动。必须**把表格区高度也锁死**：

```css
.matrix-table tbody td { height: 56px; padding: 0 16px; vertical-align: middle; }
.dash-layout > .card .matrix-scroll { flex: 1 1 auto; min-height: 488px; }
```
488 = 表头 40 + 8 行 × 56（满页高度）。

### 为什么不用 margin-top: auto 钉底
钉底能让按钮贴卡片底部，但空白会落在**表格与按钮之间**，且随行数变化 ——
按钮位置稳了，空白却在动，还是在抖。
**锁表格区高度**则让空白留在表格区**内部**（最后一行之下），
四项全恒定：行高 56、表格区 488、卡片高 648、按钮 Y 偏移 616。

→ 通用原则：**要让下游元素位置稳定，就锁它上游容器的高度，而不是把它自己钉到底部。**

### 56px 的取值依据
自然行高约 45px。取 56px 因为 8 行满页时 40 + 8×56 = 488 正好填满表格区，
底部几乎不留白。（此前 48px 时 8 行只有 424px，比 488 少 64px，那 64px 就是用户看到的底部留白。）

## 改动 013：分页链接加锚点，翻页不再跳回顶部

### 改法
1. 矩阵卡片加 `id="matrix-card"`
2. 分页链接（上一页 / 页码 / 下一页）全部追加 `#matrix-card`

   ⚠️ **必须用 `scroll-margin-top`，不能用 `margin-top`** ——

## 054（2026-08-30，版本 20260830aa）：修复页面切换「来回晃」（布局抖动）
- **现象**：概览（长页、有滚动条）切到设置/用户管理（短页、无滚动条），整页左右晃；保存后顶部 flash 移除又造成纵向跳动。

- **修复**：
  - CSS：`html { overflow-y: scroll; scrollbar-gutter: stable; }` 永久预留滚动条轨道，所有页面内容宽度恒定（短页显示灰色禁用条），消除切换横向晃。
  - JS `initFlashToast`：flash 移除时先 `maxHeight = scrollHeight` 锁定，再 rAF 把 `max-height/padding/margin` 收为 0 + `overflow:hidden`，0.4s 平滑收起，内容随之下滑而非突然上跳。
  - 版本号 `z → aa`（z 已是末位字母，改用 aa），css+js 同字母。
- **验证**：页面下发 aa 版本；CSS 含两行规则、JS 含 maxHeight/scrollHeight；逻辑上开关滚动条轨道后切换不再横向变宽变窄。
- **同步**：5 文件 → 4 份交付包；zip 替换 37 条目。纯 CSS/JS，Flask 按 mtime 热更无需重启（服务 x10iJj 持续运行）。
- **复用经验**：
  - 「切页/切长短内容时页面晃」第一嫌疑是滚动条出现/消失，全局 `overflow-y:scroll` + `scrollbar-gutter:stable` 是最稳的一招，比逐个页面凑高度省事。
